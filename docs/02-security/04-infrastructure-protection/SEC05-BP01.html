SEC05-BP01: ネットワークレイヤーを作成する

データの機密性とアクセス要件に基づいてワークロードコンポーネントを論理的にグループ化し、ネットワークトポロジを異なるレイヤーにセグメント化する

公式ドキュメント

リスクレベル

高
  • ネットワークレイヤーを確立しないと、不正アクセスや横移動のリスクが高まる
  • 多層防御の欠如により、セキュリティ境界が不十分になる
  • 検査システムの誤検知や処理オーバーヘッドが増加
レイヤー化は
防御の第一歩！
境界を明確に

3層Webアプリケーション

  • プレゼンテーション層: Amazon S3 + CloudFront CDN
  • アプリケーション層: ALB + パブリックサブネット（DMZ）
  • データ層: プライベートサブネットのDB・ファイルシステム
  • 各レイヤー境界で認可されたトラフィックのみ通過
機能別の責任分離で
明確な境界を作る！
セキュリティの基本

データ機密性による分離

  • 機密レベル別のサブネット・VPC分離
  • 異なるAWSアカウントでの強力な分離
  • 高リスクサービス（ファイルアップロード等）の独立レイヤー
  • 検査システムの誤検知防止と処理効率化
データの価値に応じて
保護レベルを調整！
適切な分離が鍵

AWSマネージドサービス

  • VPC Lattice: レイヤー間の相互運用性向上
  • Lambda: 特別な理由がない限りVPCサブネットに配置
  • VPCエンドポイント・PrivateLink: プライベート接続
  • マネージドサービスがネットワークトポロジに与える影響を考慮
AWSサービスを活用して
効率的な設計を！
統合を意識する

実装ガイダンス

  • 機能別レイヤー: プレゼンテーション・アプリケーション・データ
  • 機密性別レイヤー: データ感度レベルに応じた分離
  • 動作別レイヤー: 高リスク処理の独立配置
  • 各境界での適切な制御実装
