REL01-BP01: サービスクォータと制約を認識する

デフォルトのクォータを認識し、ワークロードアーキテクチャのクォータ増加リクエストを管理します。

公式ドキュメント

リスクレベル

このベストプラクティスを確立しないと
高リスク
が発生します！
  • サービスクォータの監視と自動管理により、障害を予防的に削減できます
  • トラフィックパターンの変化により、ベストプラクティスに従わないとサービス中断や劣化が発生する可能性があります
  • すべてのリージョンとアカウントでこれらの値を監視・管理することで、予期しないイベントでもアプリケーションの回復力が向上します

期待される成果

  • 主要メトリクスの監視に関する適切なガイドラインの実装
  • インフラストラクチャレビューの実施
  • 自動修復ステップによる検証
  • サービス劣化や中断を引き起こすサービスクォータと制約に到達しないことの確認
AWSアカウントでのサービス劣化や
中断を防ぐことができます！

一般的なアンチパターン

  • 使用するサービスのハードまたはソフトクォータとその制限を理解せずにワークロードをデプロイする
  • 必要なクォータを分析・再設定せずに、事前にサポートに連絡せずに代替ワークロードをデプロイする
  • クラウドサービスに制限がなく、レート、制限、カウント、数量を考慮せずにサービスを使用できると仮定する
  • クォータが自動的に増加すると仮定する
  • クォータリクエストのプロセスとタイムラインを知らない
  • デフォルトのクラウドサービスクォータがリージョン間で同一であると仮定する

実装ガイダンス

  • Service Quotasは250以上のAWSサービスのクォータを一箇所から管理できるAWSサービスです
  • AWS Trusted Advisorは一部のサービスの使用量とクォータを表示するサービスクォータチェックを提供します
  • デフォルトのサービスクォータは各サービスのAWSドキュメントにも記載されています
  • 一部のサービス制限（API Gatewayの使用プランなど）は、それぞれのサービス内で設定されます
  • サービスクォータはリージョン固有またはグローバルな性質を持つ場合があります
サービスクォータは運用上の
ガードレールとして機能し、
誤った過剰プロビジョニング
を防ぎます！

実装手順

サービスクォータの場合：

  • AWSサービスクォータをレビューする
  • 使用されるサービス（IAM Access Analyzerなど）を特定する
  • AWS Configを使用してAWSリソースを発見する
  • AWS CloudFormationデータを使用してAWSリソースを特定する
  • 自動監視方法を確立する
  • サービスクォータの変更を自動的にチェックする方法を確立する

サービス制約の場合：

  • リソース制約に近づいているリソースに対するアラートの監視とメトリクス方法を確立する
  • アプリケーションやシステムにとって意味のある制約を持つ各リソースのアラートしきい値を確立する
  • 制約が使用率に近い場合にリソースタイプを変更するワークフローとインフラ管理手順を作成する
