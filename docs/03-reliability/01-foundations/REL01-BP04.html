REL01-BP04: クォータを監視・管理する

潜在的な使用量を評価し、使用量の計画的な成長を考慮してクォータを適切に増加させます。

公式ドキュメント

リスクレベル

このベストプラクティスを確立しないと
中リスク
が発生します！
  • AWSサービスクォータの自動追跡と使用量監視により、クォータ制限に近づいていることを確認できます
  • この監視データを使用して、クォータ枯渇による劣化を制限できます

期待される成果

  • 管理と監視を行うアクティブで自動化されたシステムがデプロイされている
  • クォータ使用量のしきい値に近づいていることを確実に検知する運用ソリューション
  • クォータ変更リクエストによる予防的な修復
自動監視システムで
予防的な対応
が可能になります！

一般的なアンチパターン

  • サービスクォータしきい値をチェックする監視を設定しない
  • 値を変更できないハード制限の監視を設定しない
  • ソフトクォータ変更のリクエストと確保に必要な時間が即座または短期間であると仮定する
  • サービスクォータに近づいているときのアラームを設定するが、アラートへの対応プロセスがない
  • AWS Service Quotasでサポートされているサービスのみのアラームを設定し、他のAWSサービスを監視しない
  • マルチリージョン回復力設計のクォータ管理を考慮しない

実装ガイダンス

  • サポートされているサービスについて、評価してアラートやアラームを送信できるさまざまなサービスを設定してクォータを監視できます
  • これらのアラームはAWS Config、Lambda関数、Amazon CloudWatch、またはAWS Trusted Advisorから呼び出すことができます
  • CloudWatch Logsのメトリクスフィルターを使用して、ログのパターンを検索・抽出し、使用量がクォータしきい値に近づいているかを判断できます
使用量の監視により
近づいているクォータ
をアラートできます！

実装手順

監視の場合：

  • 現在のリソース消費量（バケットやインスタンスなど）をキャプチャする
  • サービスに不可欠で適用可能な現在のクォータをキャプチャする：
  • AWS Service Quotas
  • AWS Trusted Advisor
  • AWSドキュメント
  • AWS CLI
  • AWS CDK

管理の場合：

  • 自動化：AWS Configカスタムルールを設定してリージョン間でサービスクォータをスキャンし、差異を比較する
  • 自動化：スケジュールされたLambda関数を設定してリージョン間でサービスクォータをスキャンし、差異を比較する
  • 手動：AWS CLI、API、またはAWSコンソールを通じてサービスクォータをスキャンし、差異を報告する
  • リージョン間でクォータの差異が特定された場合、必要に応じてクォータ変更をリクエストする

監視ツール

  • AWS Service Quotas：250以上のAWSサービスのクォータを一箇所から管理
  • Trusted Advisor：さまざまなしきい値で現在のサービス制限を監視
  • サービスクォータ履歴：リージョンの増加をチェック
  • CloudWatch：メトリクスとログの監視
  • AWS Config：カスタムルールによる自動チェック
