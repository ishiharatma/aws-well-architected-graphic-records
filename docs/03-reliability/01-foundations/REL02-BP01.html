REL02-BP01: ワークロードのパブリックエンドポイントに高可用性ネットワーク接続を使用する

ワークロードのパブリックエンドポイントへの高可用性ネットワーク接続を構築することで、接続の損失によるダウンタイムを削減し、ワークロードの可用性とSLAを向上させます。

公式ドキュメント

リスクレベル

このベストプラクティスを確立しないと
高リスク
が発生します！
  • 高可用性で回復力のあるネットワーク接続の設計により、ワークロードがユーザーにとってアクセス可能で利用可能であることを確保

期待される成果

  • パブリックエンドポイントへの高可用性ネットワーク接続を計画、構築、運用することが重要
  • 接続の損失によりワークロードが到達不可能になった場合、ワークロードが実行中で利用可能であっても、顧客はシステムがダウンしていると認識
  • ワークロードのパブリックエンドポイントの高可用性で回復力のあるネットワーク接続と、ワークロード自体の回復力のあるアーキテクチャを組み合わせることで、顧客に最高の可用性とサービスレベルを提供
接続が失われても
ワークロードが稼働中
なら、顧客には
システムダウンに見えます！

高可用性を提供するAWSサービス

  • AWS Global Accelerator：グローバルネットワークを使用したパフォーマンス向上
  • Amazon CloudFront：コンテンツ配信ネットワーク（CDN）
  • Amazon API Gateway：APIの管理とスケーリング
  • AWS Lambda Function URLs：サーバーレス関数のHTTPSエンドポイント
  • AWS AppSync APIs：GraphQL APIの管理
  • Elastic Load Balancing (ELB)：負荷分散
  • Amazon Route 53：高可用性DNSサービス

一般的なアンチパターン

  • 高可用性のためのDNSとネットワーク接続を計画せずに高可用性ワークロードを設計する
  • 個々のインスタンスやコンテナでパブリックインターネットアドレスを使用し、DNSでそれらへの接続を管理する
  • サービスの場所特定にドメイン名ではなくIPアドレスを使用する
  • パブリックエンドポイントへの接続が失われるシナリオをテストしない
  • ネットワークスループットのニーズと配信パターンを分析しない
  • 大きな地理的エリアにコンテンツを提供する際にコンテンツ配信ネットワークを使用しない
  • 分散サービス拒否（DDoS）攻撃を計画しない

実装ガイダンス

DNS（ドメインネームシステム）：

  • Amazon Route 53などの高可用性でスケーラブルなDNSを使用してドメインのDNSレコードを管理
  • Amazon Route 53が提供するヘルスチェックを使用
  • Geo DNSと遅延ベースルーティング機能を検討

負荷分散：

  • Elastic Load Balancing (ELB)を使用してワークロード自体の高可用性を確保
  • サーバーレスソリューションにはAmazon API GatewayとAWS Lambdaを使用
ヘルスチェックは
ユーザーの行動を模倣
するように設定できます！
Webページや特定のURLの
リクエストなど

マルチリージョン戦略

  • マルチサイトActive/Active：ワークロードが複数のリージョンからトラフィックを処理
  • マルチサイトActive/Passive：アクティブリージョンからトラフィックを処理し、セカンダリリージョンにデータを複製
  • Route 53ヘルスチェックを使用してプライマリリージョンの任意のエンドポイントからセカンダリリージョンのエンドポイントへのDNSフェイルオーバーを制御

コンテンツ配信：

  • Amazon CloudFront：世界中のエッジロケーションのネットワークを使用して低遅延と高データ転送レートでコンテンツを配信
  • CDNはユーザーの近くにあるまたはキャッシュされた場所からコンテンツを提供
