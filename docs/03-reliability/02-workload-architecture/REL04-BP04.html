REL04-BP04: 変更操作を冪等にする

公式ドキュメント

リスクレベル

  • 中リスク
  • 重複処理により意図しない副作用が発生
  • 重複レコードや不整合状態を防ぐ
同じリクエストを複数回実行しても
単一リクエストと
同じ効果

冪等性の概念

  • 各リクエストが正確に一度処理される保証
  • 複数の同一リクエストが単一リクエストと同じ効果
  • 冪等性トークンでAPIリクエスト発行
  • クライアントが恐れることなくリトライ実装
冪等サービスAPIは
システム状態が変化しても
同一応答を返す

分散システムでの課題

  • 最大一回: クライアントが一回のみリクエスト（簡単）
  • 最低一回: 成功確認まで継続リクエスト（簡単）
  • 正確に一回: 複数同一リクエストが単一と同効果（困難）
  • 冪等性トークンで重複レコード・副作用なし
分散システムでは
「正確に一回」の実装が
最も困難

望ましい結果

  • 一貫性のある冪等性アプローチ
  • 十分に文書化された手法
  • 全コンポーネント・サービスで広く採用
  • すべてのコンポーネントとサービスで冪等性確保
クライアントとサーバー間の
契約を簡素化し
恐れを軽減

アンチパターン

  • 不要な場合でも無差別に冪等性適用
  • 冪等性キーとしてタイムスタンプ使用
  • 冪等性のためにペイロード全体保存
  • サービス間でのキー生成不整合
過度に複雑な
冪等性実装ロジックは
避ける

実装ステップ

  • 冪等操作の特定: POST、PUT、DELETE
  • 一意識別子使用: UUID、KSUID
  • 状態追跡・管理: トークンと状態を永続化
  • 冪等操作実装: 重複チェックと応答
包括的なテストスイートで
冪等性を
検証

AWSストレージオプション

  • Amazon DynamoDB: 低レイテンシ、高可用性NoSQL
  • Amazon ElastiCache: 高スループット、低レイテンシ
  • Amazon RDS: リレーショナルデータベース
  • Amazon S3: 高スケーラブル、耐久性オブジェクトストレージ
DynamoDBとElastiCacheは
TTL値で自動的に
トークン期限切れ

利点

  • より高いスケーラビリティ
  • 強化された信頼性
  • 改善されたデータ整合性
  • 運用の透明性
エラーハンドリングが
より簡単になり
安全にリトライ
