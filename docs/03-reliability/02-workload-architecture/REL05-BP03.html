REL05-BP03: リトライ呼び出しを制御・制限する

公式ドキュメント

リスクレベル

  • 高リスク
  • 制御されていないリトライがシステム負荷を悪化
  • リトライストームによるリソース枯渇
指数バックオフ、ジッター、
最大リトライ数で
制御

リトライ戦略

  • 指数バックオフ: 段階的に長い間隔
  • ジッター: リトライ間隔のランダム化
  • 最大リトライ数の制限
  • 最大経過時間の設定
バックオフとジッターで
意図しない協調リトライによる
トラフィックスパイク回避

望ましい結果

  • リソース消費の解放・最小化
  • バックエンドサービスの自己回復時間提供
  • 迅速な復旧と成功リクエスト処理
  • 負荷軽減によるシステム保護
ストレス下のシステム
コンポーネントが
圧迫されない

エラータイプの理解

  • 一時的エラー: リトライで解決可能
  • 永続的エラー: リトライしても解決しない
  • 権限不足: 手動介入が必要
  • 設定エラー: 修正が必要
依存関係の公開エラーコードを
理解してリトライ対象を
適切に判断

アンチパターン

  • 指数バックオフ、ジッター、最大値なしのリトライ
  • リトライ効果のテスト未実施
  • 権限・設定エラーを含む全エラーリトライ
  • アプリケーションスタックの複数層でリトライ
冪等でないサービス呼び出しの
リトライは重複結果など
予期しない副作用

実装ガイダンス

  • AWS SDKのデフォルトリトライ・指数バックオフ使用
  • 冪等サービス呼び出し時の類似ロジック実装
  • ユースケースに基づくタイムアウト・停止条件決定
  • リトライユースケースのテストシナリオ構築・実行
カスタムリトライメカニズムより
組み込み・サードパーティ機能を
優先使用

利点

  • リクエスト失敗時の望ましい結果取得
  • リソース過負荷時のサーバー復旧許可
  • ジッターによるリクエストスパイク回避
  • メタステーブル障害防止
バックオフで通常リクエスト負荷に
リトライが加わることによる
負荷エスカレーション軽減

監視とアラート

  • 繰り返しサービス障害の監視・アラート
  • 根本的問題の可視化・対処
  • 可観測性プラクティスの実装
  • 根本原因の特定・修正

根本的な問題への
対処が重要
