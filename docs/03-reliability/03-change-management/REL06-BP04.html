REL06-BP04: 応答を自動化する（リアルタイム処理とアラーム）

イベントが検出されたときに自動化を使用してアクションを実行します。例えば、障害が発生したコンポーネントを置き換えます。

公式ドキュメント

リスクレベル

中リスク

このベストプラクティスを確立しないと、手動対応による遅延や人的エラーにより、システムの復旧時間が長くなり、可用性目標を達成できない可能性があります。

期待される成果

  • リアルタイムアラームの特定と自動処理の設定
  • SLOとSLAを維持するための適切なアクション実行
  • 単一コンポーネントの自己修復からフルサイトフェイルオーバーまでの自動化
  • 障害や性能劣化の防止のための迅速な修正アクション
自動化によりMTTRを短縮し、
人的エラーを排除できます！
システムのレジリエンス向上

一般的なアンチパターン

  • 主要なリアルタイムアラームの明確なインベントリやカタログがない
  • 重要なアラーム（コンピュート枯渇時のオートスケーリングなど）に自動応答がない
  • 矛盾するアラーム応答アクション
  • アラート通知受信時にオペレーターが従うべき標準作業手順書（SOP）がない
  • 設定変更の監視不足と、意図しない設定変更を元に戻す戦略がない

自動化可能なアクション

  • コンポーネント置換: 障害コンポーネントの自動置換
  • コンピュート容量調整: Auto Scalingによる自動スケーリング
  • トラフィック再ルーティング: 正常なホスト、AZ、リージョンへの転送
  • オペレーター通知: 適切な担当者への自動通知
  • サービス再起動: 障害サービスの自動再起動
EventBridgeを使用して
システムイベントに
自動的に応答可能！

実装手順

  • 1. アラームのインベントリ作成 - AWS CLIの`describe-alarms`コマンドを使用
  • 2. すべてのアラームアクションを文書化 - 手動・自動問わずランブックに記録
  • 3. アラームアクションの設定と管理 - CloudWatch SDKを使用した自動化アクション指定
  • 4. EventBridgeルールの設定 - システムイベントへの自動応答
  • 5. 自動化の継続的改善 - 手動プロセスの自動化機会を継続的に評価

このベストプラクティスを確立する利点

  • システムレジリエンスの向上
  • 人的エラーが発生しやすい手動介入の削減
  • 可用性目標の達成
  • サービス中断の削減

監視と対応が可能になり、
