REL07-BP01: リソースの取得やスケーリング時に自動化を使用する

クラウドにおける信頼性の基盤は、インフラストラクチャとリソースのプログラム的な定義、プロビジョニング、管理です。

公式ドキュメント

リスクレベル

高リスク

このベストプラクティスを確立しないと、手動エラーや遅延により、アプリケーションやワークロード要件の変化への対応が困難になります。

期待される成果

  • Infrastructure as Code (IaC)によるインフラ管理
  • バージョン管理システム（VCS）でのインフラコード定義・維持
  • 自動化メカニズムへのAWSリソースプロビジョニングの委任
  • ALB、NLB、Auto Scalingなどのマネージドサービス活用
  • CI/CDパイプラインによるリソースプロビジョニング
IaCにより
一貫性と再現性を確保し、
手動エラーのリスクを削減！

一般的なアンチパターン

  • コマンドラインやAWSマネジメントコンソールでの手動リソースデプロイ（click-ops）
  • アプリケーションコンポーネントやリソースの密結合
  • ビジネス要件や新しいリソースタイプに適応しない柔軟性のないスケーリングポリシー
  • 予想される需要に対する手動キャパシティ見積もり

実装ガイダンス

  • Gitなどのバージョン管理システムでIaCテンプレートを保存
  • AWS CloudFormationでインフラコンポーネントを定義
  • AWS CodePipelineまたはサードパーティCI/CDソリューションとの統合
  • Auto Scalingの設定（EC2、ECS、データベースレプリカ）
  • テンプレートのリント・検証、ステージング環境へのデプロイ
自動化パイプラインにより
デプロイを高速化し、
環境間の一貫性を確保！

実装手順

  • 1. ソースコードリポジトリの作成 - インフラ設定コードを保存
  • 2. IaCソリューションの選択 - AWS CloudFormationで一貫性を保持
  • 3. CI/CDパイプラインとの統合 - デプロイの自動化
  • 4. 適切なメトリクスの決定・収集 - 自動スケーリング用
  • 5. 自動スケーリングの設定 - スケールアウト・インポリシー
  • 6. デプロイの監視 - 障害検出とロールバック機能

このベストプラクティスを確立する利点

  • アプリケーション変更と同じソフトウェア開発ライフサイクルでインフラ変更を管理
  • 一貫性と再現性の促進、手動エラーリスクの削減
  • 自動化デリバリーパイプラインによる効率的なリソース更新
  • 動的な自動リソーススケーリングの実現
  • パフォーマンスとコスト効率の改善
  • レスポンシブで回復力のあるクラウドインフラの維持
IaC + CI/CD + Auto Scaling
の組み合わせで
信頼性の高いインフラを実現！

関連ツールとサービス

  • AWS CloudFormation - Infrastructure as Code
  • AWS CodePipeline - CI/CDパイプライン
  • AWS Auto Scaling - 自動スケーリング
  • Amazon EC2 Auto Scaling - EC2インスタンス自動スケーリング
  • Elastic Load Balancing - 負荷分散
  • DynamoDB Auto Scaling - データベース自動スケーリング
