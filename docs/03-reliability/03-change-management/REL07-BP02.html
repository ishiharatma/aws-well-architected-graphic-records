REL07-BP02: ワークロードの障害検出時にリソースを取得する

可用性が影響を受けた場合に必要に応じてリソースを反応的にスケールし、ワークロードの可用性を復元します。

公式ドキュメント

リスクレベル

中リスク

このベストプラクティスを確立しないと、障害や顧客体験の劣化を検出した際に、可用性を復元するスケーリング活動が適切に開始されない可能性があります。

期待される成果

  • 障害や顧客体験劣化の検出時の迅速な対応
  • 可用性復元のためのスケーリング活動の開始
  • 自動または手動でのスケーリング実行
  • リソース不足による可用性影響の迅速な復旧
まずヘルスチェックを設定し、
可用性への影響を示す
基準を定義することが重要！

実装ガイダンス

  • ワークロードの全コンポーネントにわたる可観測性と監視の実装
  • 顧客体験の監視と障害検出
  • 必要なリソースをスケールする手順の定義（手動または自動）
  • 適切な担当者への通知または自動化の開始
可能な限り自動化を使用し、
手動スケーリングは
最後の手段として！

スケーリング手順の定義

  • AWS Auto Scaling - スケーリングプランでリソースのスケーリング指示を設定
  • Amazon EC2 Auto Scaling - Auto Scalingグループで適切なインスタンス数を維持
  • DynamoDB Auto Scaling - Application Auto Scalingでスループット容量を動的調整
  • 実際のトラフィックパターンに応じたプロビジョニング容量の自動調整

実装手順

  • 1. ヘルスチェックの設定 - 可用性への影響を示す基準を定義
  • 2. アラートメカニズムの構築 - 障害検出時の通知システム
  • 3. スケーリング手順の文書化 - 手動・自動両方の手順
  • 4. 自動スケーリングの設定 - 可能な限り自動化を優先
  • 5. スケーリング手順のテスト - 定期的な動作確認

このベストプラクティスを確立する利点

  • 障害からの迅速な復旧
  • ワークロードの可用性向上
  • 顧客体験への影響最小化
  • 自動化による人的エラーの削減
  • リソース使用量の最適化
反応的スケーリングにより
障害の影響を
最小限に抑制！

関連ツールとサービス

  • Amazon CloudWatch - 監視とアラート
  • AWS Auto Scaling - 統合スケーリングソリューション
  • Amazon EC2 Auto Scaling - EC2インスタンス自動スケーリング
  • DynamoDB Auto Scaling - データベーススループット自動調整
  • Elastic Load Balancing - 負荷分散とヘルスチェック
