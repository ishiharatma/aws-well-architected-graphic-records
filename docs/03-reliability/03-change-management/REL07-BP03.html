REL07-BP03: ワークロードにより多くのリソースが必要であることを検出した際にリソースを取得する

クラウドコンピューティングの最も価値ある機能の一つは、リソースを動的にプロビジョニングする能力です。

公式ドキュメント

リスクレベル

中リスク

このベストプラクティスを確立しないと、需要の増加に対応できず、キャパシティ不足によりサービス品質が低下する可能性があります。

期待される成果

  • 需要に応じたコンピュート・データベース・その他リソースの自動スケーリング設定
  • トラフィックバーストに対応する十分なヘッドルームの提供
  • 追加リソースがオンラインになる間のサービス継続
  • 定義されたSLO（サービスレベル目標）の遵守
従来のオンプレミスとは異なり、
クラウドでは動的プロビジョニングで
ピーク容量を事前確保する必要なし！

一般的なアンチパターン

  • スケーラブルリソースの固定数プロビジョニング
  • 実際の需要と相関しないスケーリングメトリクスの選択
  • 需要バーストに対応する十分なヘッドルームの未提供
  • 容量追加が遅すぎるスケーリングポリシー
  • 最小・最大リソース数の設定ミス

実装ガイダンス

  • ワークロードコンポーネントの水平スケーラビリティの判定
  • EC2インスタンス、ECSタスク、EKSポッドなどの水平スケーラブルコンポーネント
  • データベースリードレプリカ、DynamoDB、ElastiCacheなどの複製リソース
  • コンテナベースアーキテクチャでの2層スケーリング
水平スケーラブルコンポーネントは
同じリソースを提供し、
同一に動作する特徴あり！

スケーリングメカニズム

  • EC2 Auto Scaling - EC2インスタンスの自動スケーリング
  • Application Auto Scaling - ECSタスクのスケーリング
  • Horizontal Pod Autoscaler (HPA) - Kubernetesポッドのスケーリング
  • KEDA - イベント駆動Kubernetesオートスケーリング
  • Capacity Providers / Karpenter - コンピュートリソースのスケーリング

このベストプラクティスを確立する利点

  • ワークロードの高可用性提供
  • 定義されたSLOの遵守
  • 現在と予測される需要に対する適切なリソース量の提供
  • 需要減少時のリソース非活性化によるコスト削減
  • ピーク容量の静的割り当て不要による効率性向上
自動スケーリングにより
需要に応じたリソース提供で
可用性とコスト効率を両立！

関連ツールとサービス

  • Amazon EC2 Auto Scaling - EC2インスタンス自動スケーリング
  • Application Auto Scaling - 各種AWSサービスの自動スケーリング
  • Amazon ECS - コンテナオーケストレーション
  • Amazon EKS - マネージドKubernetesサービス
  • Amazon DynamoDB - NoSQLデータベース自動スケーリング
  • Amazon ElastiCache - インメモリキャッシュ自動スケーリング
