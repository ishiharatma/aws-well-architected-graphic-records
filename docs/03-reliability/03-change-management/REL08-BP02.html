REL08-BP02: デプロイの一部として機能テストを統合する

公式ドキュメント

リスクレベル

  • 高リスク
  • テスト不備はバグのある本番リリースを招く
  • テスト失敗の無視は予期しない動作の原因
ユニットテストと統合テストで
必要な機能を検証！
自動化が鍵

期待される成果

  • 自動化によるユニット・統合テストの実行
  • コードが期待通りに動作することの検証
  • デプロイプロセスへのテスト統合
  • テスト失敗時のデプロイ中止
TDDアプローチで
テストケースを先に作成し、
コードを検証！

テストの種類

  • ユニットテスト：最小機能単位の動作検証
  • アプリケーションの一部を分離してテスト
  • 統合テスト：機能要件に従った動作検証
  • 副作用（データ変更等）を考慮したテスト
プレプロダクション環境で
テストを実行し、
成功後に本番デプロイ！

一般的なアンチパターン

  • デプロイ加速のためのテスト失敗無視
  • デプロイパイプライン外での手動テスト実行
  • 緊急ワークフローでのテスト手順スキップ
  • 本番環境と類似しない環境でのテスト
  • 柔軟性不足で保守困難なテストスイート

実装ガイダンス

  • テスト駆動開発（TDD）アプローチの採用
  • 機能コード作成前のユニットテスト作成
  • CI/CDパイプラインへの自動テスト統合
  • Web・モバイルアプリの複数デバイステスト

AWS CodePipelineでの実装

  • 開発者のコミット時に自動変更検出
  • アプリケーションビルドとユニットテスト実行
  • ユニットテスト成功後のステージングサーバーデプロイ
  • 統合・負荷テストの実行
  • 全テスト成功後の本番デプロイ

このベストプラクティスを確立する利点

  • デプロイプロセス中の早期問題発見
  • バグや予期しない動作での本番リリースリスク削減
  • コードの期待動作とAPIコントラクトの検証
  • システムの仕様要件に従った動作検証
自動テストにより
品質保証と
リリース信頼性を向上！

関連ツールとサービス

  • AWS CodePipeline - CI/CDパイプライン
  • AWS CodeDeploy - アプリケーションデプロイ
  • Amazon EC2 - 仮想サーバー
  • AWS Lambda - サーバーレス関数
  • AWS CLI - コマンドラインインターフェース
