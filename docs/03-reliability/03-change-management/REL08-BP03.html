REL08-BP03: デプロイの一部として復旧力テストを統合する

公式ドキュメント

リスクレベル

  • 中リスク
  • 未知の問題が本番で気づかれずダウンタイムを招く
  • 人的解決への依存は障害対応を遅延
意図的に障害を導入して
破壊的シナリオでの
システム能力を測定！

期待される成果

  • 本番での劣化に耐えるシステム能力への信頼構築
  • 障害につながる弱点の特定
  • 障害と劣化の自動的・効率的軽減の改善
  • ゲームデイの一環として本番実装を目標
復旧力テストは
予期しない障害の
特定に焦点！

一般的なアンチパターン

  • デプロイプロセスでの可観測性・監視不足
  • システム障害解決の人的依存
  • 品質分析メカニズムの不備
  • 既知問題への集中と未知発見実験の欠如
  • 発見とランブックの文書化不備

復旧力テストの種類

  • 災害復旧テスト：DR計画とSOPの更新・検証
  • カオスエンジニアリング：制御された障害の導入
  • ネットワーク停止やサービス障害のシミュレーション
  • AWS Resilience Hubによる継続的復旧力評価
プレプロダクションから開始し、
最終的に本番環境での
実装を目標に！

実装ガイダンス

  • 重要なデプロイでのDR計画・SOP更新
  • 自動デプロイパイプラインへの信頼性テスト統合
  • AWS Resilience Hubでのアプリケーション定義
  • DR計画・SOP更新後の災害復旧テスト実行
  • AWS Fault Injection Serviceでの制御された障害シミュレーション

災害復旧戦略

  • バックアップ・復元 - 最もコスト効率的
  • パイロットライト - 最小限のリソースで待機
  • コールドスタンバイ - 停止状態で待機
  • ウォームスタンバイ - 縮小規模で稼働
  • ホットスタンバイ - フル規模で待機
  • アクティブ-アクティブ - 最高の可用性

このベストプラクティスを確立する利点

  • 気づかれない未知の問題の特定
  • 本番でのダウンタイム防止
  • 発見の文書化とCI/CDプロセスへの統合
  • ランブック構築による効率的・反復可能な軽減
復旧力テストにより
システムの脆弱性を
事前発見・改善！

関連ツールとサービス

  • AWS Resilience Hub - 復旧力評価・管理
  • AWS Fault Injection Service - カオスエンジニアリング
  • AWS Elastic Disaster Recovery - 災害復旧
  • AWS Systems Manager - 復旧手順文書
  • Amazon CloudWatch - 監視・アラーム
