REL08-BP04: イミュータブルインフラストラクチャを使用してデプロイする

公式ドキュメント

リスクレベル

  • 中リスク
  • インプレース変更は設定ドリフトを招く
  • 一貫性不足はデプロイ信頼性を低下
イミュータブルインフラは
本番ワークロードでの
インプレース変更禁止！

期待される成果

  • 実行中のインフラリソースへのインプレース変更禁止
  • 変更時の新しいインフラセットの並行デプロイ
  • 自動検証成功後のトラフィック段階的移行
  • ソフトウェア更新、セキュリティパッチ、設定変更への統一適用
変更が必要な時は
新しいインフラ上に
アーキテクチャを構築！

一般的なアンチパターン

  • 実行中のインフラリソースへのインプレース変更実装
  • 環境間での設定ドリフト発生
  • 手動変更による人的エラーリスク
  • 複雑なロールバック手順

このベストプラクティスを確立する利点

  • 環境間での一貫性向上とテスト簡素化
  • 設定ドリフト削減 - 既知・テスト済み状態への設定
  • 信頼性のあるアトミックデプロイ - 成功か無変更
  • デプロイ簡素化 - アップグレード対応不要
  • 高速ロールバックによる安全なデプロイ
  • セキュリティ姿勢強化 - SSH等のリモートアクセス無効化
前の動作バージョンは
変更されないため、
安全なロールバックが可能！

デプロイパターン

  • カナリアデプロイ：少数顧客を新バージョンに誘導
  • 行動変化やエラーの詳細精査
  • 重大問題発生時のトラフィック除去
  • 成功時の希望速度での継続デプロイ
  • ブルー/グリーンデプロイ：完全環境切り替え

実装ガイダンス

  • 再現性向上と人的エラー最小化のための自動化活用
  • Infrastructure as Code（IaC）の活用
  • プログラム的・記述的・宣言的定義のソース管理
  • ユーザー影響最小化のロールアウトパターン採用

関連ツールとサービス

  • AWS CloudFormation - Infrastructure as Code
  • AWS CodeDeploy - 自動デプロイメント
  • Amazon EC2 - 仮想サーバーインスタンス
  • AWS Fargate - サーバーレスコンテナ
  • Elastic Load Balancing - トラフィック分散
