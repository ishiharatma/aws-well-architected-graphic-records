REL08-BP05: 自動化を使用して変更をデプロイする

公式ドキュメント

リスクレベル

  • 中リスク
  • 手動変更は人的エラーのリスクが高い
  • 緊急時の手順省略は失敗を招く
本番システムへの変更は
多くの組織にとって
最大のリスク領域！

期待される成果

  • リリースプロセスへの自動デプロイ安全性組み込み
  • 広範囲なプレプロダクションテスト
  • 自動ロールバック機能
  • 段階的本番デプロイ
  • 開発者の本番デプロイ監視不要
デプロイは
ファーストクラス問題として
ビジネス問題と同等に解決！

一般的なアンチパターン

  • 手動変更の実行
  • 緊急ワークフローでの自動化手順スキップ
  • 加速タイムラインのための確立プロセス無視
  • ベイク時間を考慮しない迅速な連続デプロイ

CI/CDパイプライン

  • 継続的インテグレーション・デリバリー文化の採用
  • コミット・コード変更の自動ステージゲート通過
  • 自動テスト・異常検出の呼び出し
  • 本番デプロイ前のパイプライン停止
  • 変更の自動ロールバック
最も困難な運用手順こそ
自動化すべき！
人を介在させない方が安全

実装手順

  • 1. コードリポジトリの設定 - Gitベースのソース管理システム
  • 2. 継続的インテグレーションサービス設定 - AWS CodeBuild
  • 3. デプロイサービス設定 - AWS CodeDeployによる自動化
  • 4. 継続的デリバリーサービス設定 - AWS CodePipeline

このベストプラクティスを確立する利点

  • 人的エラー導入可能性の除去
  • 本番変更前のテスト能力提供
  • 本番プッシュ前の計画完全性検証
  • リリースプロセスの自動ロールバック
  • 本番問題の特定と前動作状態への復帰
自動化により
失敗デプロイの
本番影響を最小化！

関連ツールとサービス

  • AWS CodePipeline - 継続的デリバリーサービス
  • AWS CodeBuild - 継続的インテグレーション
  • AWS CodeDeploy - 自動デプロイメント
  • Git - ソースコード管理
  • Amazon EC2 - コンピュートサービス
  • AWS Fargate - サーバーレスコンテナ
