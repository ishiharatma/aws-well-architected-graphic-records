REL09-BP01: バックアップが必要なすべてのデータを特定してバックアップする、またはソースからデータを再現する

ワークロードで使用されるデータサービスとリソースのバックアップ機能を理解し、使用します。ほとんどのサービスは、ワークロードデータをバックアップする機能を提供します。

公式ドキュメント

リスクレベル

高リスク

このベストプラクティスを確立しないと、データ損失時の復旧能力が大幅に制限され、ビジネス継続性に重大な影響を与える可能性があります。

期待される成果

  • データソースが特定され、重要度に基づいて分類されている
  • RPOに基づくデータ復旧戦略の確立
  • バックアップまたは他のソースからのデータ再現能力
  • 定義されたRPOとRTO内でのデータ復旧
データの重要度を正しく評価することで、
効率的なバックアップ戦略を構築できます！
RPO/RTOの定義が鍵です

一般的なアンチパターン

  • ワークロードのすべてのデータソースとその重要度を把握していない
  • 重要なデータソースのバックアップを取っていない
  • 重要度を基準とせず、一部のデータソースのみバックアップ
  • RPOが未定義、またはバックアップ頻度がRPOを満たせない
  • バックアップの必要性や他のソースからのデータ再現可能性を評価していない

実装ガイダンス

  • AWS Backup: 複数のAWSサービスにわたるデータ保護の一元化と自動化
  • Amazon RDSとDynamoDB: ポイントインタイム復旧（PITR）をサポート
  • AWS Elastic Disaster Recovery: サーバーワークロード全体のコピーと継続的データ保護
  • Amazon S3: セルフマネージドおよびAWSマネージドデータソースのバックアップ先
  • AWS Storage GatewayやAWS DataSync: オンプレミスデータのクラウドバックアップ
データ再現の例：
ElastiCacheレプリカや
RDSリードレプリカから
プライマリ損失時にデータを再現

実装手順

  • 1. ワークロードのすべてのデータソースを特定
  • 2. 重要度に基づいてデータソースを分類
  • 3. AWSまたはサードパーティサービスを使用してデータのバックアップを作成
  • 4. バックアップしないデータのデータ再現メカニズムを確立
  • 5. データバックアップの頻度を確立

このベストプラクティスを確立する利点

  • 障害時のデータ復元と復旧能力の向上
  • 定義されたRPO/RTO内での確実なデータ復旧
  • ビジネス継続性の確保
  • データ損失によるビジネス損失の最小化
適切なバックアップ戦略は
ビジネスの信頼性と
継続性の基盤です！
