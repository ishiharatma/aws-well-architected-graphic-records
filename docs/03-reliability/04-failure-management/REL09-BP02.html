REL09-BP02: バックアップを保護し、暗号化する

認証と認可を使用してバックアップへのアクセスを制御し、検出します。暗号化を使用してバックアップのデータ整合性が損なわれることを防止し、検出します。

公式ドキュメント

リスクレベル

高リスク

このベストプラクティスを確立しないと、バックアップデータが不正アクセスや改ざんの対象となり、復旧時にデータの整合性や機密性が保証されない可能性があります。

一般的なアンチパターン

  • バックアップと復元自動化に、データと同じアクセス権限を持たせる
  • バックアップを暗号化していない
  • 削除や改ざんから保護するための不変性を実装していない
  • 本番システムとバックアップシステムで同じセキュリティドメインを使用
  • 定期的なテストによるバックアップ整合性の検証を行っていない

暗号化実装ガイダンス

  • Amazon S3: サーバーサイド暗号化とクライアントサイド暗号化をサポート
  • Amazon RDS: データベース暗号化時、バックアップも自動的に暗号化
  • DynamoDB: バックアップは常に暗号化される
  • AWS Elastic Disaster Recovery: 転送中および保存時のすべてのデータを暗号化
  • AWS KMS: データキーの作成、保存、アクセス制御
AWS KMSを使用することで、
データキーへのアクセスを
IAMで細かく制御できます！

サイバーレジリエンス考慮事項

  • AWS Backup Vault LockやS3 Object Lockによる不変性の実装
  • 論理的エアギャップによる本番環境とバックアップ環境の分離
  • AWS Backup復元テストによる定期的なバックアップ整合性検証
  • 多者承認による重要な復旧操作の認可制御
ランサムウェア対策として
不変性とエアギャップが
特に重要です！

実装手順

  • 1. 各データストアで暗号化を使用 - ソースデータが暗号化されていれば、バックアップも暗号化される
  • 2. AWS KMSを使用したキー管理 - 暗号化キーの作成、保存、アクセス制御
  • 3. IAMによるアクセス制御 - バックアップへの認証と認可の実装
  • 4. 不変性の実装 - Vault LockやObject Lockによる改ざん防止
  • 5. 定期的な整合性検証 - バックアップの復元テストと検証

このベストプラクティスを確立する利点

  • データの改ざん防止と機密性の保護
  • ランサムウェアやサイバー脅威に対する強化された保護
  • サイバーインシデント後の復旧時間短縮
  • セキュリティインシデント時のビジネス継続性向上

サイバーレジリエンスの
