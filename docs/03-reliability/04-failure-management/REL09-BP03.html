REL09-BP03: データバックアップを自動的に実行する

復旧ポイント目標（RPO）に基づく定期的なスケジュール、またはデータセットの変更に基づいて、バックアップが自動的に実行されるように設定します。

公式ドキュメント

リスクレベル

中リスク

このベストプラクティスを確立しないと、手動バックアップの失敗や忘れによりデータ損失のリスクが高まり、RPOを満たせない可能性があります。

期待される成果

  • 確立された頻度でデータソースのバックアップを作成する自動化プロセス
  • RPOに基づく定期的なバックアップの実行
  • バックアップが実行されない場合のアラート機能
  • 人的エラーの排除による信頼性の向上
自動化により一貫性と
信頼性が大幅に向上します！
手動作業のリスクを排除

一般的なアンチパターン

  • バックアップを手動で実行している
  • バックアップ機能を持つリソースを使用しているが、自動化に含めていない
  • 不規則なバックアップスケジュール
  • バックアップ失敗時の監視やアラートがない

自動バックアップサービス

  • AWS Backup: 複数のAWSサービスにわたる一元的な自動バックアップ
  • Amazon RDS: 5分間隔の継続的バックアップとPITR
  • Amazon S3: 15分間隔の継続的バックアップとバージョニング
  • DynamoDB: 継続的バックアップとポイントインタイム復旧
  • Amazon Data Lifecycle Manager: EBSスナップショットの自動化
PITR（ポイントインタイム復旧）
により、特定の時点への
精密な復旧が可能です！

バックアップ頻度ガイド

  • 重要なデータセット: 低データ損失要件 → 高頻度バックアップ
  • 一般的なデータ: 一部の損失が許容可能 → 低頻度バックアップ
  • 継続的バックアップ: RDS（5分）、S3（15分）
  • 定期バックアップ: EBS、DynamoDB、FSx（1時間間隔から）

実装手順

  • 1. 手動バックアップ中のデータソースを特定
  • 2. ワークロードのRPOを決定
  • 3. 自動バックアップソリューションまたはマネージドサービスを使用
  • 4. バックアップ計画とルールの作成
  • 5. 監視とアラートの設定

このベストプラクティスを確立する利点

  • 人的エラーの排除
  • バックアップ失敗時の即座のアラート
  • 一貫性と信頼性の向上
