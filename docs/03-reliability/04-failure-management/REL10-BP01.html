REL10-BP01: ワークロードを複数の場所にデプロイする

公式ドキュメント

リスクレベル

  • 高リスク
  • 単一障害点は可用性に重大な影響
  • 単一AZでの運用は災害リスクが高い
障害分離により
コンポーネント障害の影響を
定義された境界に制限！

期待される成果

  • 複数のアベイラビリティーゾーン（AZ）またはリージョンへの分散
  • 障害耐性と高可用性の実現
  • 境界外のコンポーネントは障害の影響を受けない
  • 複数の障害分離境界での実行による回復力向上
本番ワークロードは
最低でも2つのAZに
分散配置が必須！

障害分離の概念

  • 障害分離はコンポーネント障害の影響を定義された境界に制限
  • 適切な分離により境界外のコンポーネントは障害の影響を受けない
  • 複数の障害分離境界での実行により障害への回復力を向上
  • 火災、洪水、地震、人的エラーなどの脅威リスクを軽減
AWSサービス設計の
基本原則は単一障害点の
回避！

アベイラビリティーゾーンの特徴

  • 独立した物理インフラ（電力、バックアップ電源、機械サービス）
  • 独立したネットワーク接続による障害分離
  • 高スループット・低遅延（1桁ミリ秒）ネットワーク
  • ほとんどのワークロードで同期データ複製が可能
  • アクティブ/アクティブまたはアクティブ/スタンバイ構成

実装ガイダンス

  • すべてのコンピュートを複数AZに分散（EC2、Fargate、Lambda）
  • ロードバランサーによる利用可能AZへのトラフィック誘導
  • ワークロードデータの複数AZ複製
  • Auto Scaling、ECS、EKSによる自動コンピュート置換

このベストプラクティスを確立する利点

  • 電力・環境制御障害、自然災害への耐性向上
  • 上流サービス障害やネットワーク問題への対応力
  • より広範なEC2インスタンスインベントリへのアクセス
  • InsufficientCapacityExceptionの発生可能性削減
複数AZへの分散により
相関障害のリスクを
大幅に軽減！

関連AWSサービス

  • Amazon EC2 - 仮想サーバーインスタンス
  • AWS Fargate - サーバーレスコンテナ
  • AWS Lambda - サーバーレス関数
  • EC2 Auto Scaling - 自動スケーリング
  • Elastic Load Balancing - 負荷分散
  • Amazon EKS - マネージドKubernetes
