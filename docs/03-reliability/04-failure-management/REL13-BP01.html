REL13-BP01: ダウンタイムとデータ損失の復旧目標を定義する

公式ドキュメント

リスクレベル

  • 高リスク
  • 復旧目標の未定義
  • 恣意的な目標設定
  • 過剰投資または投資不足
目標なしに
復旧計画は立てられない！

RTO・RPOの定義

  • RTO: サービス中断から復旧までの最大許容時間
  • RPO: 最後のデータ復旧ポイントからの最大許容時間
  • ビジネス要件に基づく設定
  • 技術的考慮とのバランス
時間を測る
2つの物差し！

災害復旧マトリクス

  • クリティカル: RTO < 1時間、RPO < 15分
  • 高: RTO < 4時間、RPO < 1時間
  • 中: RTO < 24時間、RPO < 4時間
  • 低: RTO < 72時間、RPO < 24時間
重要度に応じて
階層化！

ビジネス影響分析

  • 財務影響: 収益損失・コスト増加
  • 評判影響: 顧客信頼・ブランド価値
  • 運用影響: 生産性低下・業務停止
  • 規制リスク: 法的・契約的義務
影響を多角的に
分析！

重要な質問事項

  • 最大許容停止時間はどの程度か？
  • 最大許容データ損失はどの程度か？
  • 依存関係の復旧目標は何か？
  • 時期・イベントによる変動はあるか？
  • 契約・法的義務はあるか？

  • アップストリーム: 依存元の要求事項
  • 回避策・軽減策の検討
