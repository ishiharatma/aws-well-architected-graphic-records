REL13-BP02: 復旧目標を満たすための定義された復旧戦略の使用

ワークロードの復旧目標を満たすディザスタリカバリ（DR）戦略を定義する

公式ドキュメント

リスクレベル

高
  • 計画・実装・テストされたDR戦略がない場合、災害時に復旧目標を達成できない可能性が高い
  • アドホックな復旧手順では RTO/RPO 目標を満たせない
  • 災害復旧計画の欠如は事業継続性に重大な影響
計画なしの災害対応は
必ず失敗する！
事前準備が鍵

4つのDR戦略

  • バックアップ＆リストア: RPO数時間、RTO24時間以内
  • パイロットライト: RPO数分、RTO数十分
  • ウォームスタンバイ: RPO数秒、RTO数分
  • マルチサイトアクティブ: RPOほぼゼロ、RTOゼロ
コストと復旧時間の
トレードオフを理解！
要件に応じた選択

バックアップ＆リストア

  • データとアプリケーションを復旧リージョンにバックアップ
  • 継続的バックアップでPITR（ポイントインタイム復旧）を実現
  • 災害時にインフラ展開、コード配置、データ復元を実行
  • Infrastructure as CodeでRTO短縮
シンプルで始めやすい！
AWS Backupで
一元管理

パイロットライト

  • コアワークロードインフラを復旧リージョンに事前配置
  • データレプリケーションとバックアップリソースは常時稼働
  • アプリケーションサーバーやコンピュートは未配置
  • 災害時に必要なリソースを起動・設定
最小限の炎を維持して
必要時に点火！
コスト効率的

ウォームスタンバイ

  • 縮小版だが完全機能するワークロードを常時稼働
  • 重要システムは完全複製、縮小フリートで運用
  • データはレプリケートされ復旧リージョンでライブ状態
  • 復旧時は迅速にスケールアップして本番負荷に対応
フルスケールなら
ホットスタンバイ！
最速復旧を実現

マルチサイトアクティブ

  • 複数AWSリージョンでワークロードを同時稼働
  • 全リージョンからトラフィックを積極的に処理
  • リージョン間でのデータ同期が必要
  • 書き込み競合の回避・処理が複雑
最高レベルの可用性！
ただし複雑性も
最高レベル

AWS Elastic Disaster Recovery

  • パイロットライトのコストでウォームスタンバイのRPO/RTO
  • 継続的データ保護でRPO数秒を実現
  • 復旧時のコンピュートリソース調整・オーケストレーションを自動化
  • フェイルバックプロセスも自動化支援
いいとこ取りの
マネージドサービス！
運用負荷も軽減

実装ステップ

  • 1. DR戦略決定: 復旧要件を満たす戦略選択
  • 2. パターン確認: 選択戦略の実装方法理解
  • 3. リソース評価: 復旧リージョンでの構成設計
  • 4. フェイルオーバー準備: 災害時の復旧手順定義
  • 5. トラフィック切替: Route 53等での経路変更
  • 6. フェイルバック計画: プライマリリージョン復帰手順
